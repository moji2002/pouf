# Launch checklist

Everything in this repo is built and verified. What remains are the steps only
you can do — they need your accounts. Do them in order.

The site deploys to **Vercel** at **pouf.worksonmy.dev**, a subdomain of a
domain you already own. There is no domain purchase in the critical path.

## 1. Create the GitHub repo

```bash
cd ~/Documents/my-website/pouf
gh repo create moji2002/pouf --public --source=. --remote=origin --push
```

Any other owner works too — if you move it (e.g. to an org later), update the
links in `README.md`, the site footer in `www/src/layouts/Site.astro`, and
`npm-stub/package.json`'s `repository`. GitHub redirects the old URL and carries
stars/issues across, so this is reversible.

## 2. Deploy to Vercel

```bash
vercel link --yes          # creates/links the project, root = repo root
vercel --prod              # builds and promotes
```

`vercel.json` at the repo root drives the build, and it deliberately mirrors
`ci.yml` step for step:

| `vercel.json` key | Why |
|---|---|
| `installCommand` | `bun install --frozen-lockfile` — workspaces (`registry`, `gallery`, `www`) resolve from the single root `bun.lock` |
| `buildCommand` | `git fetch --unshallow` (best-effort), then **build the registry JSON**, then build the site |
| `outputDirectory` | `www/dist` — a plain static Astro build; no Vercel adapter is installed or needed |
| `headers` for `/r/*` | `Access-Control-Allow-Origin: *` so the registry is fetchable from anywhere, plus a CDN cache with `stale-while-revalidate` |

Two things in there are load-bearing and easy to lose:

- **The registry build must run in CI/deploy, not just locally.**
  `www/public/r/**` is generated by `bunx shadcn build registry.json` *and* is
  committed. If the deploy skipped that step it would serve whatever was last
  committed, which drifts from `registry.json` silently.
- **`git fetch --unshallow`.** `www/scripts/changelog.mjs` builds the changelog
  from `git log -- registry/`. Vercel does a shallow clone, so without this the
  changelog page silently renders near-empty. It is `|| true` because the
  script already degrades gracefully — a failed unshallow costs you the
  changelog, not the deploy.

## 3. Point DNS at Vercel

`pouf.worksonmy.dev` is a subdomain, so it is one `CNAME` record on the
`worksonmy.dev` zone in Cloudflare:

| Type | Name | Target | Proxy |
|---|---|---|---|
| `CNAME` | `pouf` | `cname.vercel-dns.com` | **DNS only (grey cloud)** |

**Grey cloud, not orange.** Cloudflare's proxy in front of Vercel double-proxies
TLS and is what produced the `522` on the apex `worksonmy.dev` earlier. Vercel
issues and renews the certificate itself; it can only do that if it sees the
request.

Then attach it:

```bash
vercel domains add pouf.worksonmy.dev
```

`.dev` is on the HSTS preload list, so HTTPS is mandatory — fine, Vercel
provisions the cert automatically once the CNAME resolves.

## 4. Reserve the npm name

```bash
cd npm-stub
npm login
npm publish --access public   # ships only a README pointing at the site
```

See `npm-stub/PUBLISH.md`.

## 5. Verify the whole loop from a clean machine

```bash
# in a fresh throwaway React 19 + Tailwind v4 app with a components.json:
npx shadcn@latest add https://pouf.worksonmy.dev/r/button.json
# → components/pouf/{pouf.css,tone.ts,Button.tsx} land, and <Button/> renders cushioned.
```

If that works, Pouf is live.

## If you ever change the domain

Run one command:

```bash
bun scripts/set-origin.ts https://pouf.dev
```

It rewrites the single constant in `www/src/data/site.ts` and every absolute URL
in `registry.json`, then tells you to rebuild. **Never `sed` `www/public/r/**`
directly — it is build output; regenerate it instead:**

```bash
bunx shadcn@latest build registry.json -o www/public/r
cd www && bun run build
```

An earlier revision of this file claimed the domain appeared in only **four**
authored places. That was wrong, and it is the kind of wrong that ships a broken
install: `www/src/pages/index.astro`, `www/src/pages/docs/index.astro`,
`www/src/pages/llms.txt.ts`, `blocks/[slug].astro`, `examples/[slug].astro` and
`scripts/check-block-deps.ts` all spelled the host out too — the last one inside
a `.replace()`, where a stale value doesn't error, it just stops matching and
reports every block's dependencies as missing.

That list no longer exists, on purpose. `www/src/data/site.ts` holds the origin
and everything derives from it; `registry.json` is the one unavoidable duplicate
because shadcn fetches it as data, and `set-origin.ts` keeps the two in step.

## Nothing here requires registering with shadcn

`shadcn add <url>` installs from **any** public URL — no signup, no approval.
The registry schema is already satisfied (`$schema`, `name`, `homepage`,
`items`).

Two optional extras, neither of them blocking:

- **Registry index (namespace).** Submitting an open-source registry to
  shadcn's index gets you `npx shadcn@latest add @pouf/dashboard` instead of a
  full URL, plus discoverability via `shadcn search`. Requirements: open
  source, public, valid schema, flat layout (`/registry.json` and
  `/<item>.json` at the root), and no `content` in the source `files` array.
  Pouf meets all of these — `registry.json` carries only `path`/`type`/`target`;
  the `content` inlining happens in the **build output**, which is expected and
  is how a one-command install avoids cloning the repo.
- **A public GitHub repo with `registry.json` at the root is itself a valid
  registry.** So `moji2002/pouf` can serve installs even before DNS is live —
  the domain is not a launch blocker, only a nicer URL.
